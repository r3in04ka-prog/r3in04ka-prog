# Take it into your next project

Practical resources for building a digital product or improving a workflow. These are adaptable starting points based on my projects.

## Pick your task

| I need to… | Resource | Result |
|---|---|---|
| Explain an idea before development | [First-version product brief](templates/product-brief.md) | A primary user, a core journey and observable acceptance criteria |
| Understand a manual process | [Automation map](templates/automation-map.md) | Data sources, steps, owners and failure handling |
| Show a product without personal data | [Demo checklist](templates/demo-checklist.md) | Checks separating examples from real actions |
| Prepare a clear download | [Release card](templates/release-card.md) | The right file, first steps, update guidance and limitations |

Each file includes an example. Open it and choose **Raw** on GitHub to save or copy the Markdown. The four templates are available under [MIT](../templates/LICENSE); retain the license when redistributing them.

## Implementation notes

- [A demo that needs no API key](notes/offline-demo.md): separating scripted replies from model requests, preserving settings and checking the boundary.
- [An email client without a disk archive](notes/mail-boundaries.md): read-only inbox access, process-memory storage and the limits of those choices.

These notes describe specific versions and tradeoffs. They do not claim measured time savings or commercial impact where no measurements were taken.
